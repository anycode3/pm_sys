## 1 引言

### 1.1 背景

本平台面向大型产业链集团组织(服务中医药、低空等多产业板块,后续可拓展百类产业),是区别于传统 OA 的**产业组织协同管理平台**。建设目标(源自纪要):

1. **组织流程制衡**:协作不靠人盯人,依靠流程与数据交叉验证做制衡校验;允许人犯错,但系统规避致命性风险;
2. **风险预警**:7×24 自动识别流程异常与数据矛盾,风险早发现、根源可定位;
3. **操盘手人才培养**:人员通过参与流程学习项目全链路逻辑,平台同时是培养工具;
4. **产业资金有效落地**:资金下发后全过程可追踪,中间环节异常可识别。

需要解决的现有痛点(源自纪要):传统模式人盯人,单点失误(谎报进度、岗位缺位、竞调造假)造成重大损失;现有 OA 只做拍照打卡留痕、易造假,高层信息零散、需逐条点开、百页文档效率低;产业资金下沉难、落地过程黑箱。

**范围界定**:软件只搭建业务骨架,**财务系统不自研**(直接采购外部成熟系统集成);平台聚焦**项目、人员、流程、KPI、风险管控**。交付标准看两端:**CEO 端**(集团/站点高层)与**执行端**(基层业务人员)。

### 1.2 文档目标

本文档是整个平台的**总体需求基线**,回答:

- 平台定位、建设目标、约束(含时间与规模硬约束);
- 五大模块的职责边界与相互关系;
- 支撑"数据打通"的主数据与核心数据模型;
- **一条端到端样例业务流程如何贯穿五模块**(纪要"先跑通一条完整业务流程作为样例"的要求);
- 顶层看板与风险预警的概要需求;
- 各模块概要功能边界与待澄清问题;
- 非功能需求基线与阶段路线。

**本文档不包含**:各模块功能点级详细需求、交互原型、数据库物理设计、技术选型。按纪要实施路径,后续依次产出:交互式原型 Demo -> PRD -> 开发。

### 1.3 适用读者

决策层(评审用)、产品/需求团队、架构师、项目经理、研发团队。

### 1.4 术语与缩写

| 术语 | 说明 |
|------|------|
| 平台 | 本文档所述"产业组织协同管理平台"的总称 |
| 站点 | 站点式组织架构的基本运营单元:集团下设多个业务站点,每个站点对应负责人与团队,实行业务/财务等多权分离 |
| 架构包 | 预制的组织架构模板(按赛道/区域,如"中医药产业园架构包"),新站点导入即用 |
| 流程固化 | 正式业务指令必须走系统内固化的标准流程并完整留痕的机制(纪要的组织制衡核心载体) |
| 多权分离 | 站点内业务、财务等权限分立、相互校验的组织制衡原则 |
| KPI 数据池 | 平台统一维护的指标定义与分类框架(骨架),具体指标内容由业务方后期录入维护 |
| 六维 KPI | 纪要定义的 KPI 维度:个人、团队、公司、节点、事件、流程 |
| OKR | 目标与关键结果管理机制;本平台作为 KPI 体系的兼容增强提供(见 4.3) |
| 目标树 | 平台的目标事实骨架:集团战略目标逐层拆解,关联站点目标、项目与指标 |
| 交叉验证 | 不同业务环节产生的数据互相校验,出现矛盾即提示造假或异常的风控机制 |
| 操盘手 | 通过平台全链路流程培养的、掌握项目完整逻辑的产业经营人才 |
| 健康度 | 以红/橙/黄/绿分级表达的项目、目标、指标、人员负荷状态 |
| 上卷(Roll-up) | 下层数据按权重逐层汇总为上层结果(任务->项目->目标)的计算机制 |

## 2 总体描述

### 2.1 系统定位

**一句话定位**:面向大型产业链集团的"机构 + 平台"数据化智能体骨架 -- 以站点式组织为载体、流程固化为制衡手段、KPI 数据池为度量基线、数据交叉验证为风控机制,让 CEO 端 2 分钟看懂全局并随时下钻到人与任务,让执行端所有正式业务行为留痕可溯。

### 2.2 建设目标与成功标准

| # | 目标 | 成功标准(概要) |
|---|------|----------------|
| 1 | 数据打通:五模块共享唯一事实源 | 同一指标/项目/人员在各模块数值一致,无手工对账 |
| 2 | CEO 端 2 分钟看懂全貌 | 大屏一屏呈现站点/项目/人员/风险全貌,可下钻到子任务与个人工作状态(纪要明确验收口径) |
| 3 | 流程制衡:业务指令全留痕 | 正式业务指令 100% 走固化流程,链路完整可回溯,问题可定位到环节与人 |
| 4 | 风险预警:从事后知道到事前发现 | 四域(项目/人员/指标/数据完整性)规则可配置,预警自动产生并闭环处置 |
| 5 | 反造假:数据交叉验证 | 关键事实多源交叉比对,矛盾自动告警 |
| 6 | 骨架先行、业务填充 | KPI 指标内容、业务流程类型、产业逻辑由业务方配置录入,开发方只做骨架 |
| 7 | 人才沉淀 | 人员全流程数据留存,岗位变动/离职支持快速交接;新人经培训考试快速补岗 |

### 2.3 用户与角色

| 角色 | 端 | 核心诉求 | 主要使用模块 |
|------|-----|----------|--------------|
| 集团决策层(CEO 端) | 高层 | 大屏总览全部站点与项目,2 分钟看懂全貌,下钻到任务与人,处置预警 | 顶层看板 |
| 站点负责人(CEO 端) | 高层 | 本站点经营全貌、团队负荷、待办指令、KPI 达成 | 看板、流程、KPI |
| 站点团队负责人 | 中层 | 接收拆解任务、分派子任务、团队执行管理 | 项目、流程 |
| 执行人员(执行端) | 基层 | 接收任务、填报进度、发起/会签固化流程、培训学习 | 项目、流程、人员 |
| 评估人员 | 基层/专家 | 参与多组交叉竞调评估,工作质量绑定个人 KPI | 项目、流程 |
| KPI 管理员(业务方) | 职能 | 维护 KPI 数据池(指标内容与分类框架) | KPI |
| 系统管理员 | IT | 站点与组织、权限、流程模板、预警规则配置 | 全平台 |

> 组织形态:集团(战略层)-> 业务站点(运营单元,多权分离)-> 团队。站点可按赛道/区域批量创建(导入架构包)。

### 2.4 总体约束与假设

| # | 类型 | 内容 |
|---|------|------|
| 1 | **硬约束** | 时间基线(纪要):2026 年 8 月启动,**最快 2026 年 11 月有业务流量**,半年内完成基础版本;软件须跟上组织扩张节奏 |
| 2 | **硬约束** | 规模:启动后约半年组织规模达**万人级**,平台按万人级用户设计 |
| 3 | **硬约束** | 财务系统外购集成,不自研 |
| 4 | **硬约束** | 实施路径:严禁直接写代码,先交互式原型 Demo -> PRD -> 开发;先纵向跑通一条完整业务流程样例,再横向扩展 |
| 5 | 约束 | 平台定位为开放骨架:业务流程、考核指标、产业业务逻辑由业务方填充,开发方不预置具体产业内容 |
| 6 | 假设 | 人员投入数据由任务分摊自动汇算,不设工时填报 |

| 9 | 边界 | 系统做风险兜底,不承诺规避现实世界全部人为风险(纪要明确) |

## 3 总体架构

### 3.1 逻辑架构(四层)

```
┌───────────────────────────────────────────────────────────────────┐
│ 展示层 │ CEO 端大屏看板 + 站点工作台 + 执行端任务/流程界面 + 预警中心  │
├───────────────────────────────────────────────────────────────────┤
│ 计算层 │ 达成度上卷 · 投入汇算 · KPI 核算 · 风险规则引擎 · 交叉验证引擎│
├───────────────────────────────────────────────────────────────────┤
│ 主数据层 │ 站点组织 · 人员/人才库 · 目标树 · KPI数据池 · 项目 · 任务 ·  │
│ (唯一事实源,五模块共用 --"数据打通"的本体)            流程实例/留痕 │
├───────────────────────────────────────────────────────────────────┤
│ 采集层 │ 项目全链路填报 · 流程固化节点操作 · KPI 录入/外部采集 ·       │
│         │ 设备/AI 辅助数据 · 财务系统(外购)接口 · 事件流             │
└───────────────────────────────────────────────────────────────────┘
```

分层职责:

- **采集层**:各模块录入界面与外部数据接入(含外购财务系统、预留设备/AI/公开大数据接口);所有写入落为主数据层实体/事实,并以事件发布;
- **主数据层**:唯一事实源,五模块全部引用,不各自建数据 -- 消除信息孤岛与口径不一的根本手段;
- **计算层**:订阅事件,增量重算达成度、投入、KPI 值,运行风险规则与交叉验证规则,产生预警;
- **展示层**:面向"两端"(CEO 端/执行端)的视图;CEO 端大屏是聚合视图。

### 3.2 五模块职责边界

| 模块 | 职责(做什么) | 不做什么(边界) |
|------|----------------|------------------|
| 项目管理 | 项目全链路(意向引入->立项->竞调->建模->可研->执行)状态管理、里程碑、任务拆解与分派、进度填报、多组交叉评估调度 | 不承载审批流转(归流程固化模块);不定义指标口径 |
| 流程固化 | 业务指令类型库、固化流程模板(节点链+多权分离校验)、强制留痕、超时升级、流程 KPI 采集 | 不定义业务内容,只约束"必须走流程"这一行为 |
| 人员(人才与培训) | 人才数据库(在职+储备)、画像与履历沉淀、离职数据留存与交接、培训考试与上岗资格、人员投入汇算呈现 | 不做考核结论(归 KPI);不做薪酬 |
| KPI(含 OKR 兼容) | KPI 数据池与分类框架(骨架)、六维 KPI 方案配置、指标数据采集与核算、OKR 目标管理(可选启用) | 指标具体内容由业务方录入,开发方只做骨架 |
| 顶层看板与预警 | CEO 端大屏四视图、逐层下钻、四域预警展示与处置跟踪、全链路数据流追溯定位 | 不录入业务数据;计算依赖计算层 |

### 3.3 关键设计原则

1. **单一事实源**:任何数据只有一个权威归属模块,其余模块只引用;
2. **事件驱动**:数据变更以事件发布,计算与看板增量更新,支撑 7×24 与准实时;
3. **骨架与内容分离**:流程类型、KPI 指标内容、产业逻辑全部可配置(业务方填充),核心模型不硬编码产业细节 -- 对应纪要"开发团队只做骨架"与"开放平台"要求;
4. **制衡内建**:多权分离、交叉验证、强制留痕是平台内建机制,不是可选插件;
5. **两端交付**:CEO 端(看全局、少点击)与执行端(低负担、易操作)分别设计验收标准;
6. **流程即教材**:流程透明、全链路可回看,支撑操盘手培养定位。

## 4 主数据与核心数据关系

### 4.1 主数据清单

| 主数据 | 权威归属 | 关键属性(概要) | 被引用方 |
|--------|----------|------------------|----------|
| 站点组织 | 系统管理 | 集团->站点->团队树、多权分离配置、架构包来源 | 全部模块 |
| 人员/人才 | 人员模块 | 所属站点、岗位、履历、培训与考试记录、储备状态 | 全部模块 |
| 目标树 | KPI(OKR 启用时) | 层级、周期、权重、负责人、达成度 | KPI、项目、看板 |
| KPI 数据池(指标字典) | KPI | 六维分类框架、名称、口径、单位、周期、阈值 | KPI、流程(流程KPI)、预警、看板 |
| KPI 考核方案 | KPI | 指标×考核对象(个人/团队/公司/节点/事件/流程)×目标值×周期 | KPI、看板、预警 |
| 项目 | 项目管理 | 全链路阶段状态、关联目标、负责人、计划、预算、健康度 | 项目、看板、预警 |
| 任务 | 项目管理 | 所属项目/站点、责任人、权重、预估投入、截止、状态 | 项目、投入汇算、看板 |
| 流程实例与留痕 | 流程固化 | 指令类型、节点链、各节点意见与操作记录、时间戳 | 流程 KPI、预警、追溯 |
| 投入分摊(事实) | 系统(自动) | 人×任务×时间×投入量 | 投入汇算、预警、看板 |

### 4.2 组织模型:站点式架构

```
集团(战略层)
 ├── 业务站点 A(如:中医药某产业园)  [业务权/财务权 分离配置]
 │     ├── 团队 A1(负责人+成员)
 │     └── 团队 A2
 ├── 业务站点 B(如:低空某区域站点)
 └── ... (架构包模板批量创建:选赛道/区域 -> 导入 -> 微调)
```

- 站点是**运营与考核的基本单元**(团队 KPI、站点健康度的载体);
- 站点内**业务/财务多权分离**:同一事项的业务确认与财务核验由不同角色完成,固化流程模板内建该校验;
- **架构包模板**:预制不同赛道/区域的组织架构包,新站点导入即用,支撑组织快速复制与万人级扩张;
- 人员离职/调动时,其名下任务、流程留痕、KPI 记录完整留存并支持一键交接。

### 4.3 KPI 体系(主体)与 OKR(兼容增强)

采用纪要确认的模型:**KPI 六维体系为度量主体,OKR 作为可选的目标管理增强**。

**六维 KPI(纪要定义):**

| 维度 | 考核对象 | 示例(口径由业务方录入) |
|------|----------|--------------------------|
| 个人 KPI | 执行人员/负责人 | 任务准时率、竞调评估质量分、流程意见质量 |
| 团队 KPI | 站点团队 | 团队任务完成率、协作响应时长 |
| 公司 KPI | 集团/站点 | 经营指标、项目成功率、资金落地率 |
| 节点 KPI | 流程/任务节点 | 节点及时率、返工率 |
| 事件 KPI | 特定业务事件责任人 | 项目引入人的引入质量(立项成功率回溯) |
| 流程 KPI | 流程本身 | 流转时长、卡点率、超时率 |

**KPI 数据池与骨架分离**:开发方交付指标定义框架、分类体系、核算与预警联动机制;**具体指标内容由业务方后期录入维护**。

**OKR 兼容**:平台保留目标树骨架与 OKR 机制(目标制定、KR 度量、对齐视图),按组织单元**可选启用**;OKR 的 KR 度量同样引用 KPI 数据池中的指标,不另建口径。目标树在 OKR 未启用时仅承载集团战略目标拆解(集团->站点->项目)。

**达成度上卷**(沿用):任务完成度 -> 项目进度 -> 目标/KR 达成 -> 集团目标,按权重自动汇总。

### 4.4 核心数据流(打通机制)

| # | 数据流 | 说明 |
|---|--------|------|
| F1 | 集团战略 -> 站点 -> 任务 | 战略目标下发,拆解分配到站点、团队、子节点(纪要"高速路分段"模式) |
| F2 | 项目全链路阶段 -> 状态机 | 意向->立项->竞调->建模->可研->执行,各阶段产出物与责任留痕 |
| F3 | 业务指令 -> 流程固化 -> 留痕 | 正式指令必须经固化流程(含多权分离校验),产生流程实例与节点记录 |
| F4 | 任务/指标事实 -> 上卷与核算 | 任务状态、KPI 数据变更触发逐层重算(项目进度、KPI 值、目标达成) |
| F5 | 投入分摊 -> 人员投入汇算 | 人×任务×时间自动汇算,输出负荷(超载/闲置识别) |
| F6 | 多源事实 -> 交叉验证引擎 -> 预警 | 进度/资金/影像/设备等多源数据交叉比对,矛盾即告警 |
| F7 | 四域事实 -> 风险规则引擎 -> 预警 -> 看板 | 规则引擎订阅事件与核算结果,产生分级预警,推送 CEO 端与责任人 |
| F8 | 全流程数据 -> 人才库沉淀 | 人员参与的任务、流程表现、KPI 结果自动沉淀为履历,支持交接与培养 |

## 5 端到端样例流程主线(重点)

> 纪要要求"先跑通一条完整业务流程作为样例,其余模块以此为基础拓展"。本章以**一个产业项目从引入到执行的全链路**为样例,展示五模块如何协同。该样例同时是后续交互原型 Demo 的主线剧本。

### 5.1 样例场景

某外部合作方经标准化窗口提交一个产业项目意向(以"某中医药产业项目"为例,业务内容可替换),平台支撑其从引入到执行的全过程。

### 5.2 流程步骤与模块协同

| 步骤 | 环节 | 主导模块 | 关键动作 | 产生数据 | KPI 绑定 | 风控点 |
|------|------|----------|----------|----------|----------|--------|
| 1 | 项目引入 | 项目 | 标准化窗口登记意向,引入人实名关联 | 项目档案、引入记录 | **事件 KPI**:引入质量(后续立项/执行成功率回溯) | 外部项目必须走窗口,杜绝私通道 |
| 2 | 立项审批 | 流程固化 | 发起立项指令,走固化流程:站点业务负责人 -> 财务核验(外购财务系统) -> 集团终审 | 流程实例、节点意见留痕 | **流程 KPI**:流转时长、卡点率 | 多权分离校验;节点不可跳过;意见强制填写 |
| 3 | 竞调评估 | 项目+人员 | 调度**多组**人员从不同维度竞调;设备/AI 辅助采集(预留) | 竞调报告、影像/设备数据 | **个人 KPI**:评估质量分 | 多组交叉,规避单方汇报;采集数据防篡改 |
| 4 | 建模与可研 | 项目 | 形成可研结论与模型,与竞调原始数据比对 | 可研结论、模型数据 | **节点 KPI**:可研偏差(后续回溯) | **交叉验证**:结论与原始数据矛盾自动告警 |
| 5 | 任务拆解下达 | 项目+组织 | 集团战略下发 -> 拆解到站点 -> 团队 -> 子节点 | 任务树、责任分配 | **团队 KPI** 承接 | 站点多权分离;责任链完整 |
| 6 | 执行与指令固化 | 流程+项目 | 正式业务指令(采购/拨付申请等)走固化流程;任务进度日常填报 | 指令留痕、进度事实、投入分摊 | **个人/节点 KPI** 持续采集 | **交叉验证**:进度 vs 资金消耗 vs 影像证据 |
| 7 | 看板监控与预警 | 看板 | CEO 端大屏总览站点/项目/人员;四域预警;问题根源定位到环节与人 | 健康度、预警事件 | **公司 KPI** 呈现 | 7×24 自动识别;下钻到子任务与个人 |
| 8 | 复盘与人才沉淀 | 人员 | 项目数据归档;人员履历自动沉淀;异常人员约谈/再培训 | 人才库记录、培训记录 | 个人 KPI 累计入档 | 离职数据留存、一键交接 |

### 5.3 样例流程的两端验收(纪要交付标准)

- **CEO 端**:打开大屏,2 分钟内看懂该项目全貌(阶段、健康度、卡点、资金、责任人),可下钻到任一子任务与个人的工作状态;项目出故障时,调取全链路数据流,定位问题环节与责任人;
- **执行端**:引入人/评估人/执行人各自只需在对应环节操作系统,填报负担低;所有正式动作留痕;新人可回看全链路流程学习(操盘手培养)。

### 5.4 样例流程对原型的要求

- 交互原型 Demo 必须覆盖上述 8 个步骤的可点击闭环(允许简化数据);
- 原型评审通过后,PRD 以本样例流程为第一章展开,再横向扩展其余模块。

## 6 顶层看板需求(概要)

### 6.1 定位与用户

面向 CEO 端(集团决策层/站点负责人)的全局聚合视图,类似炒股软件的信息密度与直观性(纪要明确类比):**图文并茂、2 分钟看懂、拒绝百页 PPT**。

### 6.2 四视图

| 视图 | 回答的问题 | 数据来源 |
|------|-----------|----------|
| 站点/组织面 | 各业务站点经营健康如何? | 站点健康度、团队 KPI |
| 项目面 | 哪些项目有危险?卡在哪? | 项目全链路状态、健康度(红/橙/黄/绿)、里程碑、预算执行 |
| 人员面 | 人用得对不对?谁超载谁闲置? | 人员投入/负荷分布、人才库画像 |
| 指标面(含 OKR) | KPI 达成与目标推进如何? | 六维 KPI 值 vs 目标值/阈值、目标树达成度(OKR 启用时) |

- 全局统一**红/橙/黄/绿**健康度体系;
- 支持总览全部业务站点(纪要:既要看整体进度,也可下钻每个子任务、每个人的工作状态)。

### 6.3 下钻与根源定位

```
看板首屏(全部站点总览)
 -> 站点(组织维度)
    -> 项目(阶段、里程碑、卡点、资金)
    -> 任务/流程节点(执行细节、留痕)
    -> 人员(投入构成、负荷趋势、履历)
 -> 预警列表 -> 点击直达风险对象 + 触发规则 + 相关数据快照
```

- 每一个数字可追溯到源数据(纪要:项目故障直接调取全链路数据流定位环节与人);
- 问题根源定位是 CEO 端的**硬性验收能力**。

### 6.4 待澄清(详细需求阶段确认)

- 首屏指标卡构成与布局;大屏投放模式(指挥中心场景);
- 汇报导出(自动汇报)范围;移动端需求;
- 看板数据延迟验收口径(见 9.2)。

## 7 风险预警需求(概要)

### 7.1 四域预警框架

| 领域 | 预警信号(规则示例,阈值可配置) |
|------|--------------------------------|
| **项目域** | 阶段/里程碑逾期或临近;进度偏差超阈值;卡点(阻塞任务)停留超时;预算执行异常;项目健康度连续劣化 |
| **人员域** | 超负荷(投入汇算超上限);长期闲置;关键人单点风险(一人支撑过多关键节点);投入与岗位不匹配;异常行为模式(如评估结论长期同质化) |
| **指标域** | KPI 连续 N 期恶化或触及红线;目标达成偏差扩大(时间过半进度未过半);站点 KPI 排名持续异常 |
| **数据完整性域(交叉验证)** | 多源数据矛盾(进度 vs 资金 vs 影像/设备证据);关键证据缺失(该有影像无影像);留痕异常(流程节点意见雷同、时间异常集中);采集数据篡改痕迹 |

> 数据完整性域是纪要"反造假制衡"理念的直接落地,也是本平台区别于普通项目管理系统的核心能力。

### 7.2 预警分级与生命周期

- **分级**:红(重大,决策层介入)/ 橙(较重,站点/管理层处置)/ 黄(提示,责任方自查);与全平台健康度色系一致;
- **生命周期**:`产生 -> 通知(CEO端看板+责任人) -> 认领 -> 处置 -> 复核 -> 关闭`;超时未认领自动升级;
- **留痕**:记录触发规则、数据快照、处置过程,支持复盘与追责。

### 7.3 预警规则管理

- 规则 = 监控对象 + 指标/事件 + 阈值 + 级别 + 通知对象;
- 由系统管理员/授权角色配置,支持启停与版本管理;
- **交叉验证规则**与业务数据源强相关,初始规则集须与业务方逐条确认(见附录 A)。

### 7.4 AI 能力边界(骨架预留)

- 本期交付:风险评估的规则引擎骨架 + 外部数据/AI 接口预留位;
- 不做承诺:基于 AI 模型的自动风险评估结论(纪要提"AI 辅助",列为后续增强,待原型验证后立项)。

## 8 五模块需求概要卡

> 每张卡片含:定位、功能边界(概要)、主数据依赖、与其他模块关系、待澄清问题。详细需求由后续 PRD 阶段补充。

### 8.1 项目管理模块

- **定位**:项目全链路的事实载体与执行中枢,是上卷、投入、项目域预警的数据源头。
- **功能边界(概要)**:标准化引入窗口(内外部项目、引入人关联)/ 全链路阶段状态机(意向->立项->竞调->建模->可研->执行)/ 多组交叉评估调度 / 任务拆解分派(站点->团队->子节点)/ 进度填报 / 项目健康度自动计算 / 项目档案归档。
- **主数据依赖**:站点组织、人员、KPI 数据池、目标树(可选)。
- **与其他模块关系**:立项等关键动作触发流程固化;阶段产出供交叉验证;任务产生投入分摊;项目状态供看板与预警。
- **待澄清**:全链路各阶段产出物规范与准入条件;多组交叉评估的调度与分组规则;项目分类体系;竞调/可研模板由业务方提供的范围。

### 8.2 流程固化模块

- **定位**:组织制衡的载体--所有正式业务指令的固化流转与强制留痕(对应纪要"流程强制固化",即原型阶段的 AOA 概念)。
- **功能边界(概要)**:业务指令类型库(立项/资金拨付/采购/评估结论等,可配置)/ 固化流程模板(节点链+多权分离校验+超时自动升级)/ 节点意见强制(不同意不可无脑通过)/ 全链路留痕与回看 / 流程 KPI 数据采集(流转时长、卡点率)。
- **主数据依赖**:站点组织(多权分离配置)、人员、流程模板库。
- **与其他模块关系**:被项目/人员等模块的正式动作调用;留痕供交叉验证与追溯;流程 KPI 回流 KPI 模块。
- **待澄清**:指令类型初始清单(哪些业务动作必须走固化流程);节点链模板(含财务核验节点与外购财务系统的交互方式);意见强制填写的最低标准;超时升级规则。

### 8.3 人员模块(人才与培训)

- **定位**:人才数据库与组织赋能中枢,承载"操盘手培养"与"快速交接"两大纪要目标。
- **功能边界(概要)**:人才数据库(在职+储备,画像/标签/履历自动沉淀)/ 履历与流程数据关联(参与项目、流程表现、KPI 结果自动入档)/ 离职与调动数据留存、一键交接 / 培训考试(产业知识、平台流程,考试通过关联上岗资格)/ 人员投入与负荷呈现。
- **主数据依赖**:站点组织、人员、任务(投入分摊)、KPI 结果。
- **与其他模块关系**:为项目/流程提供人员调度依据;培训资格控制流程参与权限;履历沉淀依赖全模块留痕。
- **待澄清**:储备人才的来源与规模;培训内容与题库由业务方提供的范围;上岗资格与流程权限的绑定规则;画像维度。

### 8.4 KPI 模块(含 OKR 兼容)

- **定位**:全平台度量基线--KPI 数据池(骨架)+ 六维考核方案;OKR 为可选目标管理增强。
- **功能边界(概要)**:KPI 数据池与分类框架维护(骨架,业务方录入内容)/ 六维 KPI 考核方案配置(指标×对象×目标值×周期)/ 指标数据采集(手工录入+平台事实自动采集+外购财务系统)/ 核算与结果(达成率、趋势)/ OKR 可选启用(目标树、KR、对齐视图)/ 考核结果查看与申诉。
- **主数据依赖**:KPI 数据池、站点组织、人员、项目/任务/流程事实。
- **与其他模块关系**:指标被预警引擎引用;事件/流程/节点 KPI 依赖项目与流程模块事实;OKR 启用时目标树关联项目。
- **待澄清**:六维 KPI 的初始指标框架与分类;哪些指标可从平台事实自动采集;考核周期;申诉流程范围;OKR 启用的组织范围。

### 8.5 顶层看板与预警模块

- **定位**:CEO 端的聚合呈现与全平台风控出口。
- **功能边界(概要)**:四视图大屏(站点/项目/人员/指标)/ 逐层下钻到子任务与个人 / 四域预警列表与处置跟踪 / 全链路数据流追溯与根源定位 / 数据快照与复盘视图。
- **主数据依赖**:全部主数据的计算层结果(只读)。
- **与其他模块关系**:不产生业务数据;预警处置回写生命周期;追溯依赖各模块留痕。
- **待澄清**:首屏指标卡构成;大屏模式;汇报导出;移动端;"2 分钟看懂"的评审方法。

## 9 非功能需求

### 9.1 时间与规模约束(纪要硬约束)

| 项 | 要求 |
|----|------|
| 时间基线 | 2026-08 启动;**最快 2026-11 有业务流量**;半年内完成基础版本 |
| 用户规模 | 启动后约半年达**万人级**,按万人级设计(账号、并发、数据量) |
| 可用性 | 7×24 运行(纪要:不用管理者人工盯守);计划内维护窗口另行约定 |
| 扩张同步 | 组织快速扩张(架构包批量建站)时,平台配置即可跟上,不需定制开发 |

### 9.2 实时性与性能

| 项 | 指标(建议值,待确认) |
|----|------------------------|
| 数据延迟 | 业务数据变更到看板可感知 ≤ 5 分钟(事件驱动,目标分钟级) |
| 看板加载 | CEO 端首屏 ≤ 3 秒;"2 分钟看懂全貌"为信息设计验收标准 |
| 下钻响应 | ≤ 2 秒 |
| 预警延迟 | 规则触发到呈现 ≤ 5 分钟 |

### 9.3 安全与权限

- RBAC 权限:模块、站点范围(数据可见域)、操作三级粒度;多权分离角色互斥校验;
- 敏感数据(考核结果、人员投入、财务核验数据)按角色与站点控制;
- 关键操作(KPI 口径变更、流程模板变更、预警规则变更、架构包导入)留审计日志;
- 留痕数据防篡改(流程留痕、竞调采集数据),支持事后取证。

### 9.4 可扩展性与适配

- **骨架与内容分离**(纪要"开放平台"):业务流程类型、KPI 指标内容、产业业务逻辑全部由业务方配置填充;不修改核心模型即可接入新产业(中医药、低空、后续百类);
- **外部集成**:外购财务系统(必须);设备数据、AI 服务、公开大数据(预留);
- **扩展预警域**:风险规则引擎按"域"组织,新增域不改引擎。

## 10 阶段路线与后续澄清计划

### 10.1 阶段划分(对齐纪要实施路径)

| 阶段 | 内容 | 产出 | 时间参照 |
|------|------|------|----------|
